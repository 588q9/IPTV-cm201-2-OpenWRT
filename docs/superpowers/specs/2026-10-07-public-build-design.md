# CM201-2 公开仓库与完整离线构建设计

## 已确认的范围

在当前目录初始化公开 Git 仓库，由用户自行上传 GitHub。保留本机备份、下载资源和调试记录，但通过白名单忽略；不上传固件、密码、设备私钥、个人路径或厂商源码摘录。原创代码采用 MIT，第三方补丁保留上游授权。Markdown 全部用中文。

提供 Windows Python 3.12 + Zig 0.13.0 + 串口连接盒子的完整构建。输入为锁定的官方 OpenWrt 25.12.5 ARMv7 根系统、签名 APK 仓库、匹配源码及用户自己的原厂资源；不能以现有私人根归档作为构建输入。prepare 可联网，build 必须离线。串口一次只允许一个连接。

支持目前验证过的 Hi3798MV300、1GiB LPDDR3、原厂 3.18.24_hi3798mv2x 内核和 MT7668。容量动态化不等于支持其他硬件。前 48MiB 的八个核心分区沿用已批准尺寸；userdata 从 48MiB 开始，到实际 NAND 末尾。使用 64 位字节长度，读取物理几何与分区表交叉核对，拒绝重叠、空洞、不对齐和越界。坏块和 UBI 预留空间在 userdata 内部处理。

## 流程与接口

统一入口 tools/project.py：configure、prepare、check、build、verify、ram-test、restore。公开资源由 resources.lock.json 固定 URL、长度和 SHA256；原厂资源和串口、网络密码只保存在被忽略的 local/。输出放在被忽略的 output/。每次产物均生成新校验清单，安装资料不得依赖历史根归档或历史镜像摘要。

Windows 编译静态切根程序、串口传输程序、mtd-utils，以及旧内核兼容 ubusd。盒子在专属 /tmp 作业目录使用 apk --root 安装签名本地仓库，禁网络、禁包脚本和提交钩子；显式处理账户和启动链接。构建不得修改正在运行系统的包数据库、配置或服务。

输出规范化根归档、内部 boot、完整 RAM 测试镜像、分区表、启动校验表及安装包。同一锁定输入和配置两次构建的产物摘要应相同；设备私钥在正式启动时生成。新的安装保护读取本次产物清单，保留引导器摘要、硬件几何和核心边界检查。

## 验收

公开克隆无需私人备份即可运行纯测试；本机集成验证缺输入要明确失败。断网构建两次并比较摘要。完整新系统通过串口 RAM 启动，所有 NAND 暴露为只读，验证 procd、ubus、AP、DHCP 和 LuCI，再恢复已安装内部系统。本轮不擦除、不写入 NAND，不创建或推送远程仓库。
