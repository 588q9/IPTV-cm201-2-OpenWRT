## 修复内容

订阅下载改用专用 `/usr/libexec/cm2012-proxy-fetch`，使用 curl 8.22.0 官方头文件和设备已有 `libcurl.so.4`。该进程导出的 `mbedtls_entropy_func` 从 `getrandom(flags=0)` 获得完整内核 CSPRNG 输出，保留 curl DRBG 与 prediction resistance；该下载器不再经过 mbedTLS 的熵累积器。没有全局 LD_PRELOAD、系统 TLS 库替换、证书跳过或弱随机回退。

最初尝试仅导出平台源时，实际 libmbedcrypto 内部绑定仍调用 `/dev/random`，实机验证失败，运行时调用计数也拒绝继续。最终采用已经由前期三组对照验证有效的外部回调边界；启动及传输后的调用计数确认其实际生效，版本或绑定不符即拒绝请求。

HTTPS 和重定向都限制为 HTTPS；保留证书、主机名校验，最多三次重定向、10 秒连接和 35 秒传输限制，外层 45 秒也覆盖随机数初始化等待。响应体限 4 MiB，下载失败删除残留，URL 只通过权限 0600 的文件传递，不进入命令参数或公开日志。空响应在 YAML 解析前明确报格式无效，外层超时返回码 124 映射到下载超时。

真实服务还存在客户端标识分支：同一订阅使用 `curl/8.22.0` 返回 HTTP 200、0 字节；使用 `clash.meta` 返回 HTTP 200、11,342 字节，TLS 建立约 0.162 秒、证书验证结果 0。正式下载器采用 `clash.meta`，随后真实订阅下载和对象解析通过。这个结果只代表当次响应，不保证订阅内容和节点以后不变。
