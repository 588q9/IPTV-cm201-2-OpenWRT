# 固定原厂内核功能修复与根系统重装

## 新系统配置

默认使用 `lan=ap0`（192.168.50.1/24）、`wan=eth0`、`wwan=wlan0`。热点地址池为 .100–.150，由标准 UCI dnsmasq 管理，租约统一写入 `/tmp/dhcp.leases`。LuCI 的租约和静态租约设置使用同一服务。

无线硬件由项目 `cm2012-ap` 服务管理；默认 wpad 不启动。必须等 hostapd ENABLED 后才让 netifd 启用 lan。LuCI 的“网络 → CM201-2 无线与上联”提供热点设置、客户端状态、上游扫描和手动上联选择。初始热点和管理密码来自使用者自己的 `configure` 配置。

默认有线上联。有线上联作为可信网络，允许访问盒子管理服务；无线上联限制入站。只有选中的上联运行 DHCP 并提供默认路由和 DNS。无线支持 WPA2-PSK，STA/AP 同信道，热点跟随上游信道；不支持 WPA3-only、透明桥接或自动故障切换。

防火墙使用锁定源码构建的 iptables legacy 和 firewall3，匹配原厂内核已编译的 IPv4 过滤/NAT 接口。dnsmasq 和 NTP 的启动脚本分别绕过此固定内核不兼容的 jail，其余服务保持各自启动方式。

无线设置应用后有 90 秒确认窗口。重新连接管理页面并点击“确认可访问”；没有确认或点击“立即回滚”会恢复此前的无线 UCI 配置。无线选中后有线地址会撤下，管理请从盒子热点访问 `https://192.168.50.1`。无线上联未取得地址或无线服务失败时不能确认。已登录的新管理地址可从状态取得当前事务令牌，因此换 IP 或换浏览器后仍可确认；匿名读取和只读会话的写入均被 RPC ACL 拒绝。状态 RPC 不返回密码，前端密码留空表示保留；配置、运行配置和诊断日志仅 root 可读。SSID 使用原始字节十六进制，WPA2 密码在本机派生 PSK，避免引号和反斜杠改变凭据。整个旧系统配置不会被迁移。

## 构建及重装

先按 [构建说明](构建说明.md) 完成 `prepare`、`configure`、`check`，使用 Python 3.12：

```powershell
py -3.12 tools/project.py build --output output/new
py -3.12 tools/project.py verify --output output/new
py -3.12 tools/project.py ram-test --output output/new
```

`ram-test` 装载完整新系统，所有 NAND 分区只读，不自动挂载内部根。它检查实际分区只读标志、热点启用、服务、IPv4 NAT 和专用 RPC 后保存匹配清单的 `ram-acceptance.json`。这些基础检查不能替代有线/无线、手机转发、登录和重启实测；完成真实验收后才执行：

```powershell
py -3.12 tools/project.py install --output output/new --erase-internal-root
```

安装入口要求匹配的 RAM 基础记录及显式擦除参数。先只读核对 NAND 中两份持久分区表、保留 boot 的原厂内核、启动参数及完整维护根；维护根必须与公开构建一致，仅允许多一个标准 BusyBox `switch_root` 链接。然后重新进入安装 RAM 环境，格式化前再次核对这些内容的摘要。它核对九分区布局、NAND 几何、资源/工具摘要和未挂载目标，只执行 userdata root 阶段：格式化 UBI、创建 rootfs、解包完整系统、逐文件 SHA256 校验，最后启动内部系统。现有配置、软件和设备密钥会清除；首次启动重新生成设备密钥。保留引导器、boot 和硬件参数，不调用核心区重刷阶段。

此入口用于已经具有项目九分区布局和兼容内部启动根的盒子，不是从任意原厂 Android 布局直接安装的通用入口。`build`、`verify`、`ram-test` 不写 NAND。安装失败保留串口 RAM 环境和临时诊断目录，修复后继续；不提供旧系统增量回滚包。不要把 RAM 临时记录或含凭据的镜像公开提交。

## 回归检查

公开纯测试用 `python -m unittest discover -s tests -p "test_public_*.py"`。另外提供 `tests/device/cm2012-rpc.uc` 与 `tests/device/cm2012-wireless.uc`，在只读 RAM 系统上传到 `/tmp` 后用 `ucode` 执行；它们验证实际 ucode 参数拒绝、状态无密码、WPA2 标准/特殊字符派生向量及扫描 SSID 解码。输入均为公开测试数据，不输出实机凭据。

前端另用 Node.js 24.9.0 运行 `node tests/fixtures/cm2012-ui.cjs`，验证从另一管理地址登录、原地址的 sessionStorage 不存在时仍能确认当前事务。CI 单独运行此测试；Node.js 不参与固件构建。

## 内部系统的恢复模式提示修复

内部维护入口先挂载并核对 userdata 的 UBIFS 根，再把 `INITRAMFS=1` 交给预初始化，以跳过不适用的通用根挂载流程。原入口把此变量继续传给正式 procd，导致其缓存 `rootfs_type=initramfs`；LuCI 因而显示恢复模式警告，即使实际根系统已经是可读写 UBIFS。

根系统组装现在保留原始程序为 `/usr/libexec/cm2012/procd`，通过 `/sbin/procd` 启动包装器，仅在无参数启动、非 failsafe、内部完成标识正确、最上层根为可读写 `ubi0:rootfs` 且 UBI 来自 userdata 时清除该变量，再用 `exec` 交给原程序。原程序名称仍是 procd；预初始化热插拔参数、真正的 RAM 启动与维护回退保持原行为。两个文件均进入现有安装摘要清单，构建、安装与传输仍为纯串口。

2026-10-12 已通过串口将相同入口部署到现有盒子，原程序另备份于 `/root/cm2012-recovery-backup/procd`。本次未重新安装 userdata、未改写 boot 或分区表、未修改配置和设备密钥。修复在下次启动正式 procd 时生效；当前 PID1 已缓存的状态不会因文件替换而改变。本次仅运行已有公开测试与 Node 用例，并核对部署文件的语法、权限和摘要，重启及实机功能验收由使用者进行，不沿用旧验收结果声称本次已通过。

使用者重启后检查 LuCI 警告是否消失，并确认设置保存后再次重启仍然保留。串口可查询 `ubus call system board` 与 `cat /proc/mounts`：前者不应再返回 `initramfs`，后者应仍有可读写的 UBIFS 根。由于保留的维护根也出现在挂载表中，上游 procd 可能返回通用 `rootfs`；不要将其强制改写为 `ubifs`。需要撤回入口时，可在串口执行：

```sh
cp /root/cm2012-recovery-backup/procd /sbin/.procd-rollback
chmod 755 /sbin/.procd-rollback
mv /sbin/.procd-rollback /sbin/procd
sync
```

不要单独重装或整体升级 procd 包，以免覆盖项目入口；整体 `apk upgrade` 的限制仍适用。历史 final-c/final-d 镜像未被修改，新构建的根系统才包含本次源码修正。

## APK 软件兼容性评估

该盒子使用 ARMv7 用户空间、原厂 3.18.24 内核，约 1GiB RAM 与 7.3GiB UBIFS 空间。纯用户空间包可逐项评估；仓库中可解析、可安装不等于旧内核功能已经验收。

| 软件 | 当前评估 |
| --- | --- |
| DDNS | `ddns-scripts` 和 `luci-app-ddns` 可作为用户空间候选；按服务商补齐 curl、证书或签名工具。域名更新不提供公网入站能力。 |
| Xray | `xray-core` 的普通 SOCKS/HTTP 代理可作为候选，包依赖不强制引入内核模块；实际版本启动和连接尚未验收。透明代理需要另行适配当前 fw3/iptables，不能套用依赖 firewall4/nftables 的插件。当前已注册 REDIRECT，但未观察到 TPROXY。 |
| WireGuard | 官方 `wireguard-tools` 依赖 `kmod-wireguard`，仓库的 6.12 模块不兼容实际 3.18 内核，不能直接作为可用方案。设备已有 TUN 驱动和 `/dev/net/tun`，可以评估 ARMv7 的 wireguard-go 与相配套的 wg 工具及启动配置，但不保证仓库现成 APK 或吞吐表现。 |

依据：[DDNS 包定义](https://github.com/openwrt/packages/blob/master/net/ddns-scripts/Makefile)、[Xray 包定义](https://github.com/openwrt/packages/blob/master/net/xray-core/Makefile)、[WireGuard 包依赖](https://github.com/openwrt/openwrt/blob/master/package/network/utils/wireguard-tools/Makefile)、[用户空间 WireGuard](https://git.zx2c4.com/wireguard-go/about/)。

本次评估时盒子只有 ap0 管理路由，没有上联默认路由或 DNS；八个仓库索引刷新均失败，wget 报 `Operation not permitted`。模拟安装无法取得目标包的仓库信息，不能据此判断包不存在或不兼容。未安装上述软件，包数据库与 world 的摘要保持不变。联网后的索引更新、安装及功能验证仍待进行。
