# 固定原厂内核功能修复与根系统重装

## 新系统配置

默认使用 `lan=ap0`（192.168.50.1/24）、`wan=eth0`、`wwan=wlan0`。热点地址池为 .100–.150，由标准 UCI dnsmasq 管理，租约统一写入 `/tmp/dhcp.leases`。LuCI 的租约和静态租约设置使用同一服务。

无线硬件由项目 `cm2012-ap` 服务管理；默认 wpad 不启动。必须等 hostapd ENABLED 后才让 netifd 启用 lan。LuCI 的“网络 → CM201-2 无线与上联”提供热点设置、客户端状态、上游扫描和手动上联选择。初始热点和管理密码来自使用者自己的 `configure` 配置。

默认有线上联。有线上联作为可信网络，允许访问盒子管理服务；无线上联限制入站。只有选中的上联运行 DHCP 并提供默认路由和 DNS。无线支持 WPA2-PSK，STA/AP 同信道，热点跟随上游信道；不支持 WPA3-only、透明桥接或自动故障切换。

防火墙使用锁定源码构建的 iptables legacy 和 firewall3，匹配原厂内核已编译的 IPv4 过滤/NAT 接口。dnsmasq 和 NTP 的启动脚本分别绕过此固定内核不兼容的 jail，其余服务保持各自启动方式。

无线设置应用后有 90 秒确认窗口。重新连接管理页面并点击“确认可访问”；没有确认或点击“立即回滚”会恢复此前的无线 UCI 配置。无线选中后有线地址会撤下，管理请从盒子热点访问 `https://192.168.50.1`。无线上联未取得地址或无线服务失败时不能确认。已登录的新管理地址可从状态取得当前事务令牌，因此换 IP 或换浏览器后仍可确认；匿名读取和只读会话的写入均被 RPC ACL 拒绝。状态 RPC 不返回密码，前端密码留空表示保留；配置、运行配置和诊断日志仅 root 可读。SSID 使用原始字节十六进制，WPA2 密码在本机派生 PSK，避免引号和反斜杠改变凭据。整个旧系统配置不会被迁移。

## 构建及重装

先按 [构建说明](构建说明.md) 完成 `prepare`、`configure`、`check`，使用 Python 3.12：

```powershell
py -3.12 tools/project.py build --output output/new
py -3.12 tools/project.py verify --output output/new
py -3.12 tools/project.py ram-test --output output/new
```

`ram-test` 装载完整新系统，所有 NAND 分区只读，不自动挂载内部根。它检查实际分区只读标志、热点启用、服务、IPv4 NAT 和专用 RPC 后保存匹配清单的 `ram-acceptance.json`。这些基础检查不能替代有线/无线、手机转发、登录和重启实测；完成真实验收后才执行：

```powershell
py -3.12 tools/project.py install --output output/new --erase-internal-root
```

安装入口要求匹配的 RAM 基础记录及显式擦除参数。先只读核对 NAND 中两份持久分区表、保留 boot 的原厂内核、启动参数及完整维护根；维护根必须与公开构建一致，仅允许多一个标准 BusyBox `switch_root` 链接。然后重新进入安装 RAM 环境，格式化前再次核对这些内容的摘要。它核对九分区布局、NAND 几何、资源/工具摘要和未挂载目标，只执行 userdata root 阶段：格式化 UBI、创建 rootfs、解包完整系统、逐文件 SHA256 校验，最后启动内部系统。现有配置、软件和设备密钥会清除；首次启动重新生成设备密钥。保留引导器、boot 和硬件参数，不调用核心区重刷阶段。

此入口用于已经具有项目九分区布局和兼容内部启动根的盒子，不是从任意原厂 Android 布局直接安装的通用入口。`build`、`verify`、`ram-test` 不写 NAND。安装失败保留串口 RAM 环境和临时诊断目录，修复后继续；不提供旧系统增量回滚包。不要把 RAM 临时记录或含凭据的镜像公开提交。

## 常用功能验收范围

| 功能 | 当前判断与验证要求 |
| --- | --- |
| 网口 | RAM 与内部系统均实测 PHY 地址 2、100 Mbps 全双工、DHCP、续租请求、接口关闭/启用恢复、路由、DNS、公网收发与有线上联管理通过；未做物理拔线测试 |
| DHCP/LuCI 租约 | RAM 新租约与 LuCI 读取一致，静态租约实际分配固定地址并由 LuCI 返回；内部系统重启后用户确认 LuCI 可见手机租约，热点流量命中 NAT |
| 无线并发 | 最终 RAM 正确密码、STA/AP 信道 1/149、无线 DHCP/路由/DNS/公网收发、错误密码精确回滚与手动返回有线通过；内部系统无线连接和信道跟随复核通过。用户关闭测试手机移动数据后确认热点页面和普通网站可用，另确认上游断开时热点管理仍可访问 |
| NTP | RAM 与内部系统均实际同步到正确 UTC 时间，绕过不兼容 jail 后稳定运行 |
| SSH/HTTPS | RAM 与内部重启后实际 SSH PTY、TLS、登录页通过；用户实际 HTTPS 登录通过，匿名/只读 RPC 写入被拒绝；临时验收公钥和只读 RPC 会话已移除 |
| 配置备份 | RAM 与内部系统 `sysupgrade -b` 配置归档成功，包含专用无线配置；备份不是固件升级 |
| 定时任务 | RAM 与内部系统新增每分钟任务后实际执行成功，验收后恢复空任务配置 |
| IPv6 | 原厂内核具有 IPv6 基础接口；热点默认关闭 RA/DHCPv6，不承诺完整 IPv6 路由/前缀下发 |
| USB 存储 | RAM 与内部系统 USB 控制器加载并枚举成功；未连接磁盘，读写未验证，标准自动挂载不支持 |
| APK | 锁定离线安装通过；早期有线上游索引更新曾有两个仓库 EOF，无线上游全部索引更新成功；tcpdump-mini 及 libpcap 已实际在线安装、运行版本查询并卸载。其他包须逐项核对旧内核兼容，官方 kernel/kmod 条目不代表原厂内核兼容 |
| 系统升级 | 通用 sysupgrade、整体 APK 升级、官方通用 kmod 均不支持 |

当前盒子已从同一最终镜像完成 userdata 重建。新配置以项目模板初始化；之后用户提供的上游设置作为新配置保存，重启后持久化，当前默认有线。首次启动生成的 SSH 主机密钥和 HTTPS 密钥/证书经重启摘要复核保持不变。最终手机内部系统验收已通过；完整证据及安装中断后的维护过程见 [验收记录](验收记录.md)。

## 回归检查

公开纯测试用 `python -m unittest discover -s tests -p "test_public_*.py"`。另外提供 `tests/device/cm2012-rpc.uc` 与 `tests/device/cm2012-wireless.uc`，在只读 RAM 系统上传到 `/tmp` 后用 `ucode` 执行；它们验证实际 ucode 参数拒绝、状态无密码、WPA2 标准/特殊字符派生向量及扫描 SSID 解码。输入均为公开测试数据，不输出实机凭据。

前端另用 Node.js 24.9.0 运行 `node tests/fixtures/cm2012-ui.cjs`，验证从另一管理地址登录、原地址的 sessionStorage 不存在时仍能确认当前事务。CI 单独运行此测试；Node.js 不参与固件构建。
