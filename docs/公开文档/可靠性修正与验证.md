# 可靠性修正与验证（2026-10-17）

本轮从提交 `c8e80d1` 开始修正源码和测试，保留现有命令、UCI 配置和 ubus 方法。原 CI 失败见 [纯测试第 4 次运行](https://github.com/588q9/IPTV-cm201-2-OpenWRT/actions/runs/38419293684)。本轮没有重新安装系统或刷写 NAND 核心分区。

## 修正内容

- 后台服务取消使用 dash、bash 和 BusyBox ash 兼容的进程组信号写法。测试先验证子进程握手与会话存在，再检查取消后不能延迟写文件。CI 先安装固定 Node，再运行全部测试，两种系统互不提前取消。
- 三方回滚完整保留被其他工具修改的新增条目，并保留其他工具对已有条目的整节删除结果。未变化的匿名路由和规则按实际内容匹配，避免 UCI 临时名称变化造成重复或覆盖；无法确定身份时保留事务日志并报错。
- 路由和防火墙规则增量更新。配置读取、修改、提交及恢复失败均阻止成功响应；恢复失败不能声称已恢复，也不能清除恢复日志。旧配置缺少 `eth_role` 时仍按 WAN 解释。
- LuCI 初次读取配置失败时显示服务错误；轮询失败时显示错误并保留待确认令牌，避免把读取失败当成事务已经结束。
- 串口阶段采用整体超时与累计响应上限；初始化或退出出错仍关闭连接，并保留原始异常。保留 boot 的标准头增加加载地址等完整字段核对，继续允许明确支持的 gzip 元数据和标准 BusyBox 链接差异。
- 源码解包先验证唯一根目录，再清理指定生成目录，避免旧版本和上次补丁污染。工具链与锁定 ZIP 的文件集合及内容摘要完整比对，损坏或中断的展开缓存重新准备，验证完成后发布；拒绝链接和 Windows reparse 路径。
- hiloot 由两种 RAM 启动路径共同显式准备，不再依赖编译函数顺带解包。移除无调用的旧重启函数和未使用导入。

## 本机验证入口

Python 使用 3.12，Node 使用 CI 指定版本：

```text
python -X utf8 -m unittest discover -s tests -p "test_public_*.py" -v
node tests/fixtures/cm2012-ui.cjs
node tests/fixtures/cm2012-network.cjs
```

编译集成测试必须显式启用，读取已准备的锁定资源，生成 17 项 ARM 产物；它不读取实机凭据或连接串口。PowerShell 示例：

```powershell
$env:CM2012_RUN_COMPILER_INTEGRATION = '1'
python -X utf8 -m unittest discover -s tests/integration -p test_compiler.py -v
Remove-Item Env:CM2012_RUN_COMPILER_INTEGRATION
```

普通公开测试不运行完整编译。Windows 无 Linux 进程会话的两项测试会明确跳过；Ubuntu 必须提供 dash、bash 和 setsid，缺少能力视为失败。

## 边界

主机构建采用 Python 禁网络钩子，盒子 APK 使用 `--no-network`；这不等于物理断网。盒子运行时验证不证明新镜像已启动。本轮使用既有 Wi-Fi 上联，未使用下游终端和独立有线 WAN 完成 DHCP、NAT 或跨网段互访的端到端验收。其他 NAND 容量、断电容错、完整 Android 恢复仍保持原有边界。
