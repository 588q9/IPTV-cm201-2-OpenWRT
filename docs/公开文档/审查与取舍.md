# 公开构建审查与实施取舍

本轮进行一次独立整体审查，随后由实施者统一修复重要问题，以失败复现、修复及完整测试验证，不重复安排审查。此记录说明代码的保护行为和验收边界；原始调试日志另留本机忽略目录。

## 已修复的审查问题

- 内核执行前必须逐字读回只读 bootargs；只看到提示符不算设置成功。覆盖错误命令、旧参数、截断和重复参数。
- 移除冗余 ram-boot.img，RAM 仅通过受控串口入口装载校验内核与完整 cpio。
- 热点模板仅替换一次，不重新解释用户输入中的占位符，避免把密码写入广播名称。
- 原厂支持归档验证六个 ARM ELF 模块的真实 .modinfo/vermagic，并要求七个固件均为非空普通文件。
- 控制台激活跨串口读取边界的问题初评轻微；真机启动后发生自动等待失败，升级为重要问题并修复，累计识别提示后限频重试回车。

以上行为都有先失败后通过的回归覆盖，完整公开测试57/57通过。无线启动时真实串口输入溢出另加失败复现，Linux 控制命令采用16字节分段和10ms间隔后通过；只改变主机发送，不改变两份一致的系统产物。实际原厂切速还有两段50ms等待，YMODEM入口补等待后自动 bootstrap 从头成功。完整新系统与恢复原内部系统的实机验收已完成，具体证据见 [验收记录](验收记录.md)。

## 裁定及代价

以下保留实施过程中每项裁定，按发生顺序排列。涉及未测试场景时，说明的是交付边界，不构成这些场景已通过的保证。

- 裁定：沿用用户选择的当前目录，不创建新工作树；忽略旧实验文件而不删除，公开新接口放 tools/cm2012/，防止误用历史硬编码安装脚本。若判断有误，代价为需要回看旧文件并调整新接口。

- 任务 2 裁定：官方旧 hostapd r2 已下架且索引更新，公开构建明确锁定当前 r4 及新签名索引，不以历史 r2 缓存作为唯一可复现来源；后续完整 RAM 验证承担新版本兼容性检查。若不兼容，代价为重新锁定可获取版本并重建。

- 最终裁定：审查中内部 boot 未显式设置 ubi.mtd 的疑问不构成缺陷——原厂实际冷启动日志证实按 userdata 的 flags=32 自动追加，公开布局与既有入口一致；若该机制被误判，代价为新内部安装落入维护控制台，本轮不实际刷入。

- 最终裁定：21 项当前资源 URL 需要实际复核——发现旧 hostapd r4 已下架，锁定当前 r5、新签名索引和同版本新内容的 wifi-scripts；旧清单及缓存另存。长度、完整 SHA、索引签名与依赖已核对，21 个 URL 成功响应；若上游继续替换资源，代价为联网 prepare 停止，已有完整锁定缓存仍可离线复现。

- 最终裁定：原本将激活提示跨读边界列为轻微问题，但实际 bootstrap 已启动却自动等待控制台失败，升级为重要问题纳入当前修复——累计识别提示，并在完整提示后按一秒间隔有限重试回车；分块提示与首次回车丢失用例复现超时后通过。代价为激活过程中最多每秒发送一次回车，未出现激活提示时绝不发送。

- 最终裁定：审查未裁定 Windows 编译与两次离线复现——必须以本机执行结果交付，不用纯测试代替；若未完成则不能声称可复现。

- 最终裁定：审查未裁定原厂 Android 起点——当前实机为已装内部 OpenWrt，验证的是不依赖历史根归档的独立 RAM 工作机及 BootROM 入口；原厂 Android 控制台起点与回到 Android 的自动识别不作实测承诺。若 Android 起点有差异，代价为使用者需先分析控制台及重启条件。

- 最终裁定：审查未裁定新 RAM/AP/DHCP/LuCI/恢复——这些仍必须做实机验收和手机连接，旧系统结果不能沿用；若失败继续修复而不提交通过记录。

- 最终裁定：审查未裁定原生 C 传输真实拔线及终端恢复——交付实际双向 CRC/SHA 传输和故障模拟覆盖，不做物理拔线注入；若实际拔线触发未覆盖问题，代价为作业中止并保留 RAM 临时文件，不能声称物理拔线已验证。

- 最终裁定：审查未裁定 NAND 写入、断电与坏块——本轮明确不刷写，新写入保护仅做纯测试和真实 shell 模拟，不把它当成闪存断电容错证明；代价为今后正式安装前必须单独验证。

- 最终裁定：审查未裁定 4/16GiB 真机——只做合成布局测试，当前真机为 8GiB；代价为其他容量仍需验证几何和硬件，不能称已实测支持。

- 最终裁定：审查未裁定完整 Android/额外硬件/USB 恢复——现有备份并不完整，公开恢复说明明确边界，不作这些保证；代价为不能凭本项目资料承诺回到完整 Android。

- 最终裁定：审查未裁定最终法律合规——检查署名、许可证、源码来源说明与公开边界，保留 LGPL 正文，不分发生成固件；代价为使用者另行分发系统时仍须逐项处理对应源码与原厂资源授权。

- 最终裁定：所谓断网构建验收采用主机 Python 禁网络钩子及盒子 APK --no-network；没有断开电脑物理网络，不能将二者混称。若子进程出现未约束联网行为，代价为需另做 OS 级网络隔离；本次 Zig 使用本地锁定源码，不执行外部下载步骤。

- 最终裁定：保留上游 LGPL 正文与补丁上下文的原始字节，用精确路径的 Git 空白属性排除格式造成的误报，不删除法律文本末尾空行或补丁上下文空格；若判断有误，代价为这两个特定文件的相关空白告警不再提示，许可证 SHA 和补丁应用测试仍保留。
