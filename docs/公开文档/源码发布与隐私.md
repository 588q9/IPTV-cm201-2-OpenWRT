# 源码发布与隐私

本版隐私检查重点是实际 root 密码/密码 hash、订阅、WiFi 密钥、DDNS/API Token 的记录和处理。Linux 权限是保护手段之一；root hash 和含密钥的归档仍是秘密，不能视作已脱敏内容。

## 数据保存与公开范围

- configure 隐藏输入密码，在本机生成 root hash；本机 `local/config.json`、设备 `/etc/shadow`、必要镜像/恢复归档会保存 hash。AP 密码和原厂身份也可能在产物中。
- 订阅存在设备私有 UCI、短期下载文件和事务备份。代理 API 密钥还在 secret、active/candidate/previous 和必要备份中；状态接口不返回密钥或订阅完整 URL。
- 用于恢复的完整备份可能必须包含凭据，仅供受信管理员保存。公开诊断应脱敏；不要把完整备份、固件或现场日志作为问题附件。
- 标准 DDNS 的只读配置角色可读取 `uci ddns`，包括其中 Token；该角色不是纯状态查看者。自定义代理/无线只读 RPC 使用专用字段，不开放整个秘密 UCI 包。
- `local/`、`output/`、备份和缓存不进入源码发布。公共二进制仅允许资源锁中准确列明 SHA256 的签名索引快照。

本次保护修正包括：外层作业0700、敏感归档/日志0600；局部 umask 保持串口环境和镜像内权限；Cloudflare 令牌经 stdin 传给 curl，初始化编码也不把密码放入 awk argv；日志在输出前脱敏；增量包严格验证并使用本机 updater，阻止危险链接。

构建和刷机继续要求原有 root 上下文，维护工具保持执行权限，MTD 写入标志、分区和显式擦除门槛不放宽。HTTPS 管理策略按使用者要求留待后续，本版保持现有连接行为。

## 检查命令

使用 CPython 3.12，在仓库根目录运行：

```powershell
# 当前待公开候选（忽略目录不参与）；本机额外比对真实密码/hash，不回显其值
py -3.12 tools/cm2012/publication.py --working --known-config local/config.json
# 暂存区实际字节，避免检查工作文件却提交了其他内容
py -3.12 tools/cm2012/publication.py --index
# 已提交公开树
py -3.12 tools/cm2012/publication.py --ref HEAD
# 从提交树生成的源码附件，直接检查归档，不解包到磁盘
py -3.12 tools/cm2012/publication.py --archive .\local\release\source.tar.gz
```

检查输出只含规则、文件和行号。它覆盖高置信度私钥/token/password-hash、URL 内嵌凭据或令牌、私有路径/产物和未批准二进制；预留测试域名只豁免对应的样例 URL 规则，不豁免密钥/hash/实际秘密匹配。检查不是“无任何隐私风险”的证明，提交和附件还须人工核对。

## 验证与发布

公共回归不读取私人输入、不访问设备；Node fixtures 覆盖策略、事务、界面、更新和恢复。CI 在 Windows/Ubuntu 使用 Python3.12 与 Node24.9.0，并以只读仓库权限检查公开树。

已准备锁定缓存时，可运行仅本机编译的集成测试：

```powershell
$env:CM2012_RUN_COMPILER_INTEGRATION = '1'
py -3.12 -m unittest discover -s tests/integration -p test_compiler.py -v
Remove-Item Env:CM2012_RUN_COMPILER_INTEGRATION
```

预发布只从核定的 Git commit 生成源码包，附文件清单和 SHA256；不打包工作目录。更新包的 manifest 摘要只验证内容一致性，不证明来源身份，install 仍要求操作者信任本地生成/已核验包。

本轮代码回归、合成凭据测试和离线编译不代表真实订阅、Cloudflare 更新、Tailscale 登录/蜂窝访问、UDP 转发、重启恢复或长期观察通过。真实订阅未从现场读取，因此不对现场既有配置/日志作“从未泄露”的结论。历史验收见 [版本与验收记录](版本与验收记录.md)。

## 生成与发布源码附件

在 CPython 3.12 下使用明确的已核定提交生成附件，输出只能位于已忽略的 `local/` 子目录或 Actions 的 `RUNNER_TEMP` 子目录，已有输出目录一律拒绝覆盖：

```powershell
py -3.12 tools/cm2012/source_release.py --ref <核定的完整提交SHA> --tag v0.2.0-rc.1 --output local/release/v0.2.0-rc.1
```

工具读取提交中的 blob 和 Git 文件模式，保留执行位；工作区修改、未跟踪文件和忽略文件不会进入附件。打包前检查提交内容，打包后重新读取并检查归档，二进制例外仍限于已审核的五份索引快照及准确摘要。`source.tar.gz` 使用 `cm201-2-system-<tag>/` 前缀和固定元数据；`manifest.json` 记录提交、tag、每个文件的路径、Git mode、字节数与 SHA256；`SHA256SUMS` 可校验归档和清单。

合并到 `main` 且修改源码发布工具或工作流时，`源码预发布` Actions 自动运行；也可在 `main` 手动运行并指定尚未使用的 `v主.次.修订-rc.正整数` tag，默认 `v0.2.0-rc.1`。发布先复用 Windows/Ubuntu 只读公共检查，通过后只在发布作业使用临时 `GITHUB_TOKEN` 的仓库内容写权限，从该事件的准确 SHA 创建预发布。tag 使用只创建接口绑定事件 SHA，回读确认后以 `--verify-tag` 创建 Release；并发占用、回读不符或已占用但尚无 Release 的 tag 都会拒绝发布，不强制更新或删除 tag。已存在的 Release 只会跳过，不复核或认可其原有内容；失败后应使用新的未占用 tag，不覆盖已有附件。源码附件在临时目录全部写入并核验后才整体重命名为输出目录，写入失败不会留下半成品输出，可修复原因后重试。

本版还包含 [节点 DNS 缓存防复发](节点DNS缓存防复发-20261102.md)：固定合成探测、DNS组故障切换和限频缓存恢复；不向状态或日志写入节点/订阅信息，新代码尚未进行设备验收。
