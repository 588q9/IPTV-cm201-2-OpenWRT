# 无线中继、网口切换与 IPv4 静态路由

LuCI 入口为「网络 → CM201-2 无线、网口与路由」。本功能更新项目运行时及当前盒子，不重装系统。本次没有重新打包、启动新的固件镜像。

## 网口与热点

选择 LAN 时，eth0 与热点 ap0 由 netifd 桥接到 br-lan，保持现有 LAN 地址和标准 DHCP 服务；上联方式自动选择 Wi-Fi。必须提供有效的上游 SSID 和 WPA2 密码，密码留空保留已有值。后端拒绝 LAN 与有线上联的组合。

选择 WAN 时，eth0 恢复 DHCP 客户端，热点 ap0 继续承担 LAN。可以选择有线或无线上联，eth0 不会同时属于 LAN 和 WAN。旧配置没有 `eth_role` 时按 WAN 解释；未来新构建也默认 WAN。

热点开关与网口角色独立。LAN 模式关闭热点后，eth0 的 LAN 地址与 DHCP 服务继续工作；无线断开时仍保留本地有线管理。原厂无线驱动要求 hostapd 就绪后再配置 AP 管理地址，运行时保留该顺序，并向 netifd 登记驱动创建的外部无线设备。

下游设备处于 AP／桥接模式时，其客户端与盒子热点共用 LAN 网段，不需要额外静态路由。「透传 DHCP」指 AP 转发客户端的 DHCP 请求和回复，由盒子分配地址、网关及 DNS。下游 AP 自身若仍开启 DHCP 或存在管理地址冲突，需使用者处理。

## 静态路由与互访

本页支持新增、修改、删除、启用或停用 IPv4 路由。目标必须是规范 CIDR，例如 `192.168.60.0/24`；下一跳为真实可达的路由器地址，可留空表示直连路由；接口为 `lan`、`wan` 或 `wwan`，metric 为 0–65535。拒绝非法输入、重复条目和额外默认路由。仅保存配置并不证明下一跳或远端网络可达。

路由保存为标准 UCI `network route`，由 netifd 安装。接口暂时不可用时保留配置并显示未生效，接口恢复后自动安装。状态根据实际内核路由与接口状态判断。本页只管理标记 `cm2012='1'` 的条目，保留标准 LuCI 或用户创建的其他路由；页面提供标准路由管理入口。

「允许上游访问下游」默认关闭。开启时必须填写允许的上游来源 CIDR，多个网段用逗号或空格分隔。仅允许指定来源转发到 LAN 网段及经 LAN 到达的已启用路由目标，并对返回这些来源网段的流量设置 NAT 例外；公网出口继续使用 NAT。保留用户已有规则和 NAT 例外。

上游主路由还需有到盒子 LAN／独立下游子网的回程路由，下游独立路由器也需允许转发并具备返回路径。本次不修改上下游路由器。第一版不包含 IPv6、策略路由及额外默认路由管理。

## 确认与恢复

点击「应用设置」后，90 秒内重新连接管理界面并点击「确认可访问」；也可立即回滚。服务未就绪时拒绝确认。事务独占，不能覆盖尚未确认的设置。切换过程中热点可能短暂重启。

统一备份 `cm2012/network/dhcp/firewall`，持久事务日志位于 `/etc/cm2012-transaction`。提交失败、手动回滚、服务失败后未就绪超时以及未确认时重启，均恢复事务前配置。启动恢复服务 START=18，先于 netifd。记录完整应用快照后采用三方差异恢复，保留其他管理工具同时添加的无关路由、规则和列表项；部分提交时按完整备份恢复。后台检查使用独立进程会话，回滚前取消服务子进程；恢复失败时保留日志并阻止启动继续，以便维护恢复。服务在恢复配置后异步启动，管理连接可能需等待数秒。

原厂 `3.18.24_hi3798mv2x` 内核实测会被现代 netifd 的桥设备参数触发内核错误。本项目为 netifd 加载专用 `cm2012-netlink-compat.so`，忽略桥设备的 `IFLA_INFO_DATA` 参数，保留桥创建和端口管理。适用范围为本项目的基本 eth0/ap0 桥接，不能据此承诺高级桥参数、STP 或 VLAN 功能。原始 netifd 保留在 `/usr/libexec/cm2012/netifd`；构建产物检查要求同时包含入口、原程序及兼容库。
