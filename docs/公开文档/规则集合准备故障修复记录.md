## 已确认的原因

主订阅可以下载并解析，包含 35 个 HTTP 规则集合。旧服务在 providers 阶段将规则集合限制为 32 个，尚未下载集合就抛出 `Provider limit`；公开错误将这个数量问题误归为“订阅中的节点或规则集合下载失败”。

实际规则同时使用 YAML 和 text。继续验证发现原始 GitHub 规则域名的 TLS 连接被重置，独立 curl、强制 IPv4/TLS 1.2 及 OpenSSL 均复现；曾短暂握手成功，因此不能断言是固定 IP 故障、DNS 污染或纯 SNI 拦截。GitHub 官方 Contents API 对同一首规则成功返回 200、证书验证通过，解析得到 37 条规则。

部分原始 URL 使用 `refs/heads/<branch>/...`，初版转换错误地把 `refs` 当成分支。已经通过离线用例修正为保留 heads/tags 引用命名空间；尚未对修正后的实际规则进行新增 API 请求验证。

## 已安装的修正

- 规则集合上限 64，节点集合仍为 32；提前检查配置和集合结构，累计解析 JSON 限 16 MiB。
- 按 YAML/text 解析；文本支持 BOM、CRLF、注释，保留原策略校验与资源边界。
- 区分数量、格式、协议、TLS、HTTP 和超时错误，避免将数量限制伪装为下载失败。
- 准备好受限 GitHub 官方接口回退和有界 RAM 缓存，但 `settings.github_rule_api` 默认关闭，现有 UCI 未改动。回退仅适用于明确的无令牌 GitHub 原始规则 URL；不会处理主订阅或发送节点、主订阅地址、Token。

API 模式保留证书和主机名校验、HTTPS-only 重定向、4 MiB 响应限制及超时；403/429 单独分类。规则缓存限 64 项、16 MiB、最多一小时，使用 URL/格式摘要作为键，校验文件类型、大小、内容摘要并重解析。缓存不持久到磁盘镜像；锁异常时跳过缓存，仍保留下载和配置检查。缓存先于最终语义编译保存，若上游修复了格式合法但语义无效的规则，可能需要等待缓存到期。

GitHub 官方内容接口支持 raw 媒体类型读取原文件，匿名接口通常按出口 IP 限制为每小时 60 次；有界缓存用于减少重复调用。[内容接口说明](https://docs.github.com/en/rest/repos/contents#get-repository-content)、[频率限制](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)
